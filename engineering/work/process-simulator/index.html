The challenge

Multiple simulated nodes need to make scheduling decisions while contributing to one coherent result. The challenge was to coordinate concurrent execution and keep process-state transitions understandable.

System architecture

  1. Input workload

    Process definitions and scheduling parameters

  2. Concurrent nodes

    POSIX threads, ready and blocked queues

  3. Process trace

    Synchronised results and expected-output cases

Implementation decisions

Model the work explicitly

Each node tracks ready and blocked work using priority queues. Scheduling and process-state transitions are represented directly in C.

Coordinate concurrent nodes

POSIX threads execute simulated nodes. Mutexes protect shared results while the scheduler handles priority and pre-emption.

Check against expected traces

The repository includes input cases and expected process traces. These make it possible to compare scheduler behaviour across different workloads and thread counts.
